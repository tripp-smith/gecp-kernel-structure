# TRIQS provider runtime

This optional environment supplies TRIQS 4.0.2, CT-HYB 4.0.1 and MaxEnt 4.0.1
on Python 3.12, NumPy 2.2.6 and SciPy 1.18.1. It is separate from the default
kernelgecp pip environment. The base package and immutable 1.1.0 release are
unchanged. The provider-runtime CI runs Linux x86_64 and macOS arm64 separately.

## Install and execute

From the repository root, create a dedicated environment:

```bash
conda env create --name kernelgecp-triqs --file environments/triqs.yml
conda run --no-capture-output --name kernelgecp-triqs \
  python scripts/providers/triqs_smoke.py --output artifacts/triqs.json \
  --source-revision "$(git rev-parse HEAD)"
python scripts/providers/verify_receipt.py artifacts/triqs.json \
  --provider triqs --source-revision "$(git rev-parse HEAD)"
```

The environment uses conda-forge native libraries. MaxEnt is supplied by its
official PyPI wheel, with the complete wheel URL and SHA-256 pinned in the YAML;
it is not an available conda-forge package named `triqs_maxent`. NumPy, SciPy and
Matplotlib are resolved by conda before this wheel is installed. Do not install
these providers into the base environment or let a subsequent pip dependency
resolution replace the native numerical stack.

The probe sets BLAS/OpenMP thread limits before importing providers, then checks
the observed thread pools. It requires a single rank. Plain Python uses TRIQS's
serial MPI support when no MPI launcher is active; its diagnostic warning is
retained on stderr. This is not a parallel-MPI test. Provider output, including
native C++ output, goes to stderr; stdout and `--output` contain a JSON receipt.

## What actually executes

The probe requires exact provider release versions and Python 3.12. It imports
the actual TRIQS 4 modules `triqs.gfs` and `triqs.mesh`, using the modern
`Gf(mesh=MeshImFreq(...))` interface. It then runs:

- A 64-point fermionic Matsubara mesh, independently checked against ordinary
  integer indices and `(2*n+1)*pi/beta`, with both frequency signs. Native
  Green-function arithmetic produces a one-pole resolvent checked against its
  analytic formula to absolute error below `1e-12`.
- An interacting CT-HYB calculation at `beta=4`, interaction `U=1`, 200 measured
  cycles, 50 warmup cycles and fixed random seed. The 257-point time mesh avoids
  the provider's undersampled-Fourier warning. Both spin blocks must contain
  finite nonzero measured Green functions, with a finite nonzero average sign.
- A Bryan MaxEnt minimization on a fixed seeded two-pole time-data fixture,
  three alpha values and 81 real-frequency points. All three returned spectra
  must be finite, nonnegative and nonzero, with finite nonnegative chi-squared.

These are runtime calculation gates. They do not establish interacting-DMFT
convergence, a material-specific prediction, Monte Carlo error bars, unique
spectral recovery or analytic-continuation accuracy. Those are later application
acceptance gates. Missing imports, wrong versions, a mismatched source revision,
failed numerical checks or exceptions yield `status="failed"` and a nonzero
exit code. No mock, numerical fallback or import-only pass is used.

Receipts record actual versions, all check outcomes, numerical metrics, source
revision, probe/specification hashes, the MaxEnt wheel hash, platform and a hash
of the resolved conda package identities. Personal environment prefixes, URLs,
authentication data and user paths are excluded from the JSON identity.

## Executed macOS lock and evidence

The macOS arm64 environment was actually installed and all three provider
calculations executed locally on 2026-10-26, using Python 3.12.16. The one-pole
maximum error was `2.7769124835677133e-17`, CT-HYB's average sign was `1.0`, and
the smallest of the three MaxEnt chi-squared values was `15.530791831413705`.
OpenBLAS and OpenMP each reported one thread. These figures describe the
bounded smoke fixture, not an application benchmark.

`locks/triqs-osx-arm64-conda-explicit.txt` was exported from that actually run
environment and binds all 131 conda packages with artifact SHA-256 hashes.
MaxEnt is separately pinned in `locks/triqs-maxent-pip.txt`. Replay into a new
environment with:

```bash
conda create --name kernelgecp-triqs-locked \
  --file environments/locks/triqs-osx-arm64-conda-explicit.txt
conda run --name kernelgecp-triqs-locked python -m pip install \
  --no-deps --require-hashes --only-binary=:all: \
  -r environments/locks/triqs-maxent-pip.txt
```

This lock is macOS arm64 only. Linux's actual explicit lock is generated by CI
after successful import and numerical execution; a cross-platform dependency
solve is not execution evidence. Final committed-source receipts and full
repository acceptance belong in the phase PR and provider CI artifacts.

The initial local probe failed at import because it incorrectly requested
`triqs.meshes`; the installed TRIQS 4 module is `triqs.mesh`. This failure is
retained separately from subsequent successful calculations. Failed receipt

failed log SHA-256:
